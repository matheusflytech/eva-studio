Runbook operacional

Conectando o WhatsApp e o Instagram oficiais

O caminho completo, do zero, pra sair de "conectado via QR code" pra rodar como um negócio verificado na plataforma da Meta — WhatsApp Cloud API e Instagram Messaging.

Isso não é uma tarefa de código: é um processo administrativo (documentos, verificação, revisão de app) que só a conta Meta da Beeno pode fazer. O papel do Eva Studio nisso é receber o resultado — um phoneNumberId, uma waba, um token — e usar pra falar com a API. Esse documento mapeia os dois lados.

WhatsApp — já tem código pronto no Eva Studio Instagram — processo de conta mapeado, adaptador de código ainda não existe
00

Fundação — antes de escolher canal

WhatsApp e Instagram são dois "produtos" dentro do mesmo app Meta. Essa parte só se faz uma vez, e vale pros dois.

1

Portfólio de negócios no Meta Business Manager

Precisa existir uma conta empresarial da Beeno em business.facebook.com — CNPJ, endereço e um domínio próprio (o site institucional já serve). Se já existe uma pra outra finalidade (anúncios, página do Instagram), reaproveita.

2

Verificação da empresa (Business Verification)

Dentro do portfólio: Configurações do negócio → Central de segurança → Verificação do negócio. Pede documento do CNPJ e prova de domínio (registro DNS ou upload de arquivo no site). É o pré-requisito que mais trava quem não se planeja com antecedência — leva de algumas horas a poucos dias.

3

Criar o app em developers.facebook.com

Tipo "Empresa" (Business), associado ao portfólio verificado acima. É esse mesmo app que vai ganhar os produtos "WhatsApp" e "Instagram" nas próximas fases — um app único cobre os dois canais.

Por que isso importa desde já Como o Eva Studio atende vários clientes diferentes com o mesmo app (não é uso próprio de uma única empresa), a Meta classifica isso como app de "Tech Provider" — o que exige Advanced Access nas permissões de mensageria via App Review, não só o acesso padrão. Isso é decidido lá na frente (fase 04), mas a estrutura de portfólio/verificação já precisa estar certa desde o início pra não ter que refazer.
01

Canal WhatsApp — Cloud API

O caminho recomendado hoje é sempre a Cloud API hospedada pela própria Meta (não o On-Premises, que a Meta vem descontinuando). É o canal que o Eva Studio já tem código pronto pra receber.

1

Adicionar o produto "WhatsApp" ao app

No painel do app: Adicionar produto → WhatsApp → Configurar. A Meta cria automaticamente um número de teste temporário — dá pra testar o fluxo todo antes de ter o número real da empresa.

2

Criar a WhatsApp Business Account (WABA) e registrar o número real

O número que os clientes vão ver (ex: o número principal da Beeno, ou um número dedicado por cliente). Precisa ser um número que ainda não tenha um app do WhatsApp comum instalado com ele, ou estar disposto a migrar.

3

Gerar um token de acesso permanente

Um usuário de sistema (System User) no Business Manager, com papel de admin na WABA, gerando um token sem expiração — o token de teste padrão do painel expira em 24h e não serve pra produção.

4

Configurar o Webhook

No produto WhatsApp do app: Configuration → Webhook. URL de callback: https://<seu-domínio>/api/webhooks/meta. "Verify token": qualquer string escolhida (vira META_WEBHOOK_VERIFY_TOKEN). Campo pra assinar: messages.

5

Cadastrar e aprovar os modelos de mensagem

No painel Meta: WhatsApp Manager → Modelos de mensagem. Cada modelo (nome, idioma, texto com {{1}}, {{2}}...) leva de algumas horas a 48h pra ser aprovado. É o mesmo nome e ordem de variáveis que depois vão ser cadastrados de novo no Eva Studio (fase 03) — combine os dois na hora de criar.

Onde isso já existe no código src/app/api/webhooks/meta/route.ts já sabe validar o desafio do webhook, receber mensagens/toques de botão e responder — inclusive já decide entre texto livre e modelo aprovado sozinho, com base na janela de 24h (ver docs/CHATBOT_ENGINE.md §6). Falta só o que está na fase 03: as credenciais reais.
02

Canal Instagram — Messaging API

Direct messages do Instagram, pelo mesmo tipo de app Meta. Só funciona pra contas Business ou Creator — perfil pessoal não entra na API de jeito nenhum.

1

Converter (ou confirmar) a conta como Instagram Business/Creator

Feito direto no app do Instagram: Configurações → Conta → Mudar para conta profissional.

2

Escolher a via de conexão

Instagram API with Instagram Login (mais nova): a conta faz login direto, sem precisar de uma Página do Facebook vinculada — caminho recomendado hoje pra quem está começando agora.

Alternativa mais antiga (ainda ativa): vincular a conta a uma Página do Facebook e usar a Messenger Platform com o produto Instagram — só vale a pena se a Beeno (ou o cliente) já depende de uma Página existente pra outra coisa.

3

Adicionar o produto "Instagram" ao mesmo app

Painel do app → Adicionar produto → Instagram. Configura o login/token e o webhook (mesma ideia do WhatsApp: URL + verify token, mas endpoint e formato de payload são diferentes).

4

Permissão instagram_business_manage_messages

É essa permissão específica que libera ler/enviar DM. Pra atender contas de clientes (não só a própria conta da Beeno), precisa do mesmo Advanced Access via App Review da fase 04.

A regra da janela de 24h também existe aqui Igual o WhatsApp: só dá pra responder livremente até 24h depois da última mensagem que a pessoa mandou. O Instagram não tem "modelo pré-aprovado" pra mandar fora da janela — passado esse prazo, simplesmente não dá pra iniciar contato ali (diferente do WhatsApp, que tem essa válvula de escape via template).
O que falta do lado do código O src/app/api/webhooks/meta/route.ts de hoje só entende o formato de payload do WhatsApp (phone_number_id, mensagens de texto/interativas). O Instagram manda um formato diferente (identifica pelo igsid, não por telefone) — vai precisar de um branch novo nessa mesma rota (ou uma rota irmã) quando for a hora de ativar de verdade. O motor de conversa (advanceConversation) não muda: ele já é agnóstico de canal, só o adaptador de entrada/saída é que falta.
CONTAS PRONTAS DOS DOIS LADOS — AGORA LIGA NO EVA STUDIO
03

Ligar as credenciais no Eva Studio

Duas partes: variáveis de ambiente (uma vez, pro app inteiro) e uma linha por agente conectado (uma vez por cliente/número).

Variáveis de ambiente (Vercel → Settings → Environment Variables)

META_APP_SECRET=... # painel do app → Configurações básicas
META_WEBHOOK_VERIFY_TOKEN=... # escolhida na fase 01, passo 4

Por agente conectado — tabela eva_studio_meta_connections

CampoDe onde vem
phoneNumberIdWhatsApp Manager → número → "ID do número de telefone"
wabaIdWhatsApp Manager → visão geral da conta
accessTokenToken permanente do System User (fase 01, passo 3)

Hoje isso só entra via inserção direta no banco — ainda não existe uma tela de "conectar clicando um botão" (o fluxo de Embedded Signup da Meta) pra esse canal. É um bom próximo passo quando o volume justificar, mas não bloqueia o primeiro cliente real.

Modelos de mensagem — cadastrar nos dois lugares

O nome e a ordem das variáveis cadastrados no WhatsApp Manager (fase 01, passo 5) precisam ser digitados de novo, idênticos, na aba do agente em "Modelos de mensagem" (campos metaTemplateName / metaLanguageCode). Não existe hoje uma chamada que confirme automaticamente que os dois batem — o Eva Studio confia em quem cadastrou.

04

Virar produção de verdade

Tudo acima já funciona em modo de desenvolvimento, só visível pros administradores do app. Pra atender clientes de verdade, falta uma etapa administrativa final.

1

Submeter pra App Review

Pedindo Advanced Access de whatsapp_business_management (+ whatsapp_business_messaging) e, se for ativar Instagram também, instagram_business_manage_messages. Isso é obrigatório porque o app atende WABAs/contas de clientes diferentes — não é uso interno de uma conta só.

2

Prazo esperado

Turnaround médio de revisão em torno de 24–48h depois de submetido, desde que a verificação do negócio (fase 00) já esteja concluída — é o motivo de deixar essa parte pronta com bastante antecedência.

3

Modo Live

Com Advanced Access aprovado, o app muda de "Em desenvolvimento" pra "Ativo" no painel — a partir daí qualquer WABA/conta Instagram de qualquer cliente pode ser conectada, não só as que estão na lista de testadores.

Antes de pedir revisão A Meta pede uma tela/vídeo mostrando o uso real do produto (o painel do Eva Studio + uma conversa real fluindo) e uma política de privacidade pública. Vale gravar isso com um agente de teste já funcionando de ponta a ponta, não deixar pra fazer às pressas na hora de submeter.

Glossário rápido

WABAWhatsApp Business Account — a conta que "dona" o(s) número(s) de telefone conectados.
System UserUsuário técnico do Business Manager, sem login humano — dono do token permanente.
Advanced AccessNível de permissão liberado só via App Review, necessário pra atender contas de terceiros (não a própria).
Janela de 24hPrazo depois da última mensagem do contato em que o negócio pode responder livremente (ver docs/CHATBOT_ENGINE.md).
igsidId de usuário escopado ao app, usado pelo Instagram no lugar de telefone.
