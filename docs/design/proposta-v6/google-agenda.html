O que precisa existir por trás (para você decidir)

Login com o GoogleApp OAuth no Google Cloud da Eva, escopo calendar.readonly (só leitura). Esse escopo é "sensível": para uso aberto o Google exige verificação do app (tela de consentimento, política de privacidade, alguns dias). Até lá funciona com até 100 usuários de teste.
Banco (novo)Uma tabela de conexões por usuário (conta Google, token de atualização criptografado, agendas escolhidas). Os eventos não precisam ser guardados: o servidor busca no Google quando o calendário abre (com cache curto). Mexe em banco de produção, por isso só com o seu ok.
OutlookMesmo desenho com Microsoft Graph, numa segunda etapa.
Vincular ao CRMSe o convidado da reunião tem o e-mail de um contato, a reunião aparece ligada ao contato/negócio ("vinculado"). Só leitura, sem gravar nada.

Perguntas

  • Só leitura (recomendo para começar) ou também criar evento a partir de uma tarefa/reunião do CRM?
  • Cada pessoa vê só a própria agenda, ou o gestor vê a da equipe?
  • Google primeiro e Outlook depois, ou os dois juntos?
  • Pode criar o app OAuth no Google Cloud da Eva (precisa de quem administra a conta Google da empresa)?
  • Ok criar a tabela de conexões no banco?
